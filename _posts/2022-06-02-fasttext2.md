In the [previous post](/productembedding/), I used fasttext to learn product embeddings and talked about why it works so well. Today I want to look at what fasttext is doing under the hood, and two useful things that fall out of it: user-brand affinities for free, and an idea for the cold start problem.

## What matrix is fasttext factorizing?

We now [know](https://proceedings.neurips.cc/paper/2014/file/feab05aa91085b7a8012516bc3533958-Paper.pdf) that word2vec is secretly a matrix factorization. The matrix has a row for each word and a column for each context (the surrounding words), and each cell measures how strongly they go together. Word2vec factorizes this matrix stochastically.

In market basket terms, words and contexts become users and items, so the matrix is a user-by-item matrix.

So what does fasttext factorize? Here's how [Bojanowski et al.](https://arxiv.org/pdf/1607.04606.pdf) describe it:

```
Each word w is represented as a bag of character n-gram. 
We add special boundary symbols < and > at the beginning 
and end of words, allowing us to distinguish prefixes and
suffixes from other character sequences. We also include 
the word w itself in the set of its n-grams, to learn a 
representation for each word (in addition to character n-grams)

```

So you can think of fasttext as word2vec with extra columns added to the matrix, one for each n-gram that appears inside the words. Each cell holds the pointwise mutual information between a context and that n-gram.

## Users and attributes, for free

It gets interesting for products. As in the last post, an item is represented by itself plus its attributes:

	Example: Product_12123 ~ T-shirt + Blue Color + brand Nike + Dry Fit + ...

Now the extra columns are attributes, so a cell links a user to an attribute: how much this user is into Nike, or into T-shirts in general.

That means you can read user-brand and user-category affinities straight out of the embedding, without training a separate model for them.

## What about user attributes?

Fasttext uses item attributes to enrich items. That already helps with the cold start problem for new items: as long as you know a new item's attributes, it gets a decent embedding.

What if you supplied user attributes too, like interests, and factorized them together with the items? That would help with the cold start for new users. Think of how Spotify asks for your favorite genres when you sign up.

You could even pull out associations between generic user attributes and generic item attributes, for example which kinds of users go for which kinds of products.
